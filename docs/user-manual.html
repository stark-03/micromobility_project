1 · What this application is

Cities are filling up with e-scooters, shared bicycles and e-bikes. Somebody has to decide where those vehicles should be, whether a new bike lane is worth building, and what happens to the city when it rains. Today those decisions are usually made on intuition and tested by actually building the thing.

This application is a virtual copy of Belagavi where you can test a decision before anything is built. It has four jobs:

It does thisWhich meansWhere you see it
MonitorsShows live traffic congestion on the real street networkLive
PredictsForecasts how many trips each area will need, using machine learningData
PlansFinds routes between two points — fastest, safest or greenestPlan
SimulatesRuns a whole simulated day under a policy you choose, and measures itSim
OptimisesWorks out where vehicles should be moved, and produces crew tasksFleet
The street map is real — 9,212 actual road segments imported from OpenStreetMap, covering 832 km of Belagavi. The trips and vehicle data are synthetic, generated with realistic daily and weekly patterns, because real rider data is personal information the project does not have.

2 · Starting the application

Three services have to run together: the web interface, the API, and a Python service that does the mathematics. One command starts all of them.

Every time you want to use it

# from the project folder
npm run demo:check   # checks everything is ready, and says how to fix it if not
npm run demo         # starts all services

Then open http://localhost:5173 in your browser. Press Ctrl-C in the terminal to stop everything.

What each port is

PortServiceDo you open it?
5173The web interfaceYes — this is the application
4000API (data, accounts, rules)No, except the public feed
8000Python service (routing, forecasting, simulation)No — the browser never talks to it
If npm run demo fails with EADDRINUSE, an old copy is still running. Free the ports and try again:
fuser -k 4000/tcp 5173/tcp 8000/tcp

First-time setup only

If the database has never been prepared on this machine, run these once, in order:

npm install
conda activate micromobility && pip install -r apps/ml/requirements.txt
npm run db:create && npm run db:migrate
npm run db:seed          # loads the demo city — PRINTS PASSWORDS, copy them
npm run demand:backfill  # six weeks of trip history
npm run rollup           # builds the analytics tables
npm run db:seed generates new passwords for the demo accounts each time it creates them. Copy what it prints. Do not run it just before a demonstration — the passwords you wrote down will stop working.

Creating your own account

  1. Open http://localhost:5173. You land on the sign-in page.
  2. Click Create an account at the bottom.
  3. Fill in your name, email, and a password of at least 10 characters containing a letter and a digit. Mobile number is optional.

Four things every screen does

Every screen handles four situations explicitly, so you are never left looking at a blank page wondering:

  • Loading — grey placeholder shapes while data arrives.
  • Empty — a message telling you what to do to get data, not just "no data".

5 · Live — the traffic map

Live /live Everyone

The city as it is right now. Real Belagavi streets, with traffic congestion painted on the main roads.

What you are looking at

  • The base map — real streets, from OpenStreetMap. Zoom in far enough and street names appear.
  • Coloured lines — congestion on the 1,736 monitored main roads. Side streets stay uncoloured, exactly as real traffic services show them.
  • Dashed outlines — the eight city zones, with their names.

Reading the colours

The scale runs from free flow through yellow and orange to heavy or jammed. The legend on screen shows the full ramp.

Panels on this screen

LabelWhat it tells you
City congestionAverage congestion across every monitored road, 0 to 1
Corridors monitoredHow many road segments are reporting traffic
Mean speedAverage speed on the selected road
LengthHow long the selected road segment is
CongestionCongestion on the selected road, as a percentage

How to use it

  1. Drag to pan; scroll or use + / − to zoom.
  2. Click any coloured road to select it. Its name, speed, length and congestion appear.
  3. Watch for a few seconds — colours change on their own as new traffic readings arrive, roughly every three seconds.
There is an Offline map toggle. The normal map downloads street tiles from the internet; if you have no connection the tiles will not load. Switch to the offline map and you still get zones and congestion, drawn without any downloaded imagery.

6 · Plan — your journey

Plan /plan Everyone

Pick where you are and where you are going. The application finds three different routes, shows which vehicles you could take, and points out charging stations along the way.

The layout

Controls on the left, map on the right. On a narrow screen or phone the controls sit above the map.

Step by step

  1. Set your pickup. Click anywhere on the map. A blue pin marked A drops there. The banner at the top of the map tells you what the next click will do.
  2. Set your destination. Click again. A gold pin marked B drops there.
  3. Routes appear automatically. There is no "search" button to find — as soon as both pins exist, three routes are calculated.
  4. Choose a route by clicking one of the three cards. The map redraws it in blue; the other two stay as faint grey lines so you can see they take different streets.
  5. Change your vehicle using the Vehicle dropdown if you want. Routes recalculate for the new vehicle.

The two pin rows

Each row shows a coloured letter, the label (Pickup or Destination), and the coordinates once set. Before you set one it reads not set — click the map. Once set, a Clear button removes it. The highlighted row is the one your next click will fill.

Two shortcuts

ButtonWhat it does
Use my locationAsks the browser for your GPS position and uses it as pickup
Sample tripInstantly drops both pins on two city zones — the quickest way to see a result
Use my location usually fails on localhost, and that is normal. Browsers only allow location access on secure (HTTPS) pages, and http://localhost is not one. The screen tells you this and asks you to click the map instead. Use Sample trip if you want a result immediately.

The three routes

RouteWhat it optimises for
fastestTime. Will use busy roads and go over hills.
safestLit streets, bike lanes and quieter roads. Usually takes longer.
greenestLeast climbing and least traffic, to save battery.

Each card shows the journey time and distance. Click one to expand it into four measures:

MeasureMeaningBetter when
ETAEstimated journey time in minutesLower
DistanceLength of the route in kilometresLower
RiskSafety score out of 100 — higher means riskierLower
EnergyBattery used, in watt-hoursLower
A measure shown in green means this route is the best of the three on that measure. This is the point of the screen: the fastest route is rarely also the safest, and the trade-off is what you are choosing between.

Available near your pickup

Vehicles you could actually walk to, within 1.2 km of pin A, nearest first. Each row shows:

  • A coloured dot for the vehicle type — scooter, bicycle, e-bike, shared EV.
  • Its reference code and how far you would walk.
  • Its battery percentage. Below 20% it turns red. Hover it to see the remaining range in kilometres.

Only vehicles marked available appear. One that is already booked, being ridden, or in the workshop is not shown, because you could not take it.

Charging on the way

Charging stations within 700 m of the route you selected, nearest first, with the number of charge points, the power in kW, and the distance from your route. Choosing a different route re-checks — the safest route may pass different stations than the fastest.

If there are none, the screen says so and tells you a planner can add one from the Admin screen.

You may see a line saying your pins were snapped up to some distance to the nearest road. Routes must start and end on an actual street, so if you click on a rooftop or a field, the application moves your pin to the closest road and tells you how far it moved. It is not losing your input — it is being honest about adjusting it.

7 · Sim — testing a policy

Sim /sim View: all · Run: planner, admin

This is the heart of the project. A scenario is a set of choices about the city — how many vehicles, what the weather is, whether there are bike lanes. Running one simulates a whole day and measures what happened.

The four scenarios that come with it

ScenarioWhat it changes
Baseline — typical weekdayNothing. The city as it runs today.
Protected bike lanesSegregated bike infrastructure in the four central zones
Overnight rebalancingVans redistribute idle vehicles every 45 minutes
Monsoon day12 mm of rain across the city
Each scenario changes exactly one thing from the baseline. That is deliberate — it means any difference in the results is caused by that one change and nothing else. This is a controlled experiment, the same idea as a science practical.

Running one

  1. Click a scenario in the left column. Its details fill the right side.
  2. Press Run simulation.
  3. A progress bar appears. A full simulated day takes about a fifth of a second, so it may finish before you finish reading this.
  4. Results appear as six tiles.

The six result tiles

TileMeaning
Trips servedJourneys that found a vehicle and completed
Unmet demandPeople who wanted to travel but could not
Service ratePercentage of demand that was served
Mean waitAverage seconds spent walking to a vehicle
UtilisationPercentage of time the fleet was actually in use
Incidents / 1000 kmExpected safety incidents per thousand kilometres

Why demand went unmet

Underneath the tiles is a line explaining the reason. On the baseline scenario every unmet trip reads no charged vehicle — not "no vehicle nearby". The vehicles exist; their batteries are flat.

This is the most valuable thing the simulator produces. The answer it gives a planner is build charging infrastructure, not buy more scooters. Nobody programmed that conclusion — it emerged from the simulation.

Demand through the day

A chart of trips served (blue) and unmet demand (gold) across 24 hours. The two commuter peaks — morning and evening — are clearly visible.

Comparing two scenarios

  1. Run at least two scenarios so there is something to compare.
  2. Select the scenario you want to examine.
  3. In Compare against, choose another scenario.
  4. A table appears: each measure, its value in both runs, and the change.

Changes are labelled better or worse with an arrow, not just coloured — so the meaning survives a black-and-white printout or a colourblind reader.

A negative number is not automatically bad. Fewer unmet trips is an improvement even though the number went down. The word beside it tells you which way to read it.

The seed line

Under the results you will see something like seed 42 · 199 ms · same seed reproduces this run exactly. The seed is the starting point for all the randomness in the simulation. Same seed plus same scenario always gives identical results — which is what makes the simulation evidence rather than an opinion.

Creating your own scenario

  1. Press New at the top of the scenario list. (Planner or admin only.)
  2. Give it a name and, ideally, a sentence saying what you are testing.
  3. Set the window — how many hours, and what time of day it starts.
  4. Set the fleet — how many scooters, e-bikes and bicycles.
  5. Set the weather — rainfall in mm and temperature.
  6. Set the policy levers: which zones get bike lanes, which are closed, a demand multiplier, and whether rebalancing runs.
  7. Press Create scenario, then run it.
Change one thing from the baseline. If you change the fleet and the weather at once, you will not know which caused the difference.
A short run that starts at midnight covers the quietest hours of the day and produces almost no trips. If you choose 6 hours, set the start to 07:00 or 17:00 so it covers a rush hour.

Use the Status and Mode dropdowns to filter, and the pager at the bottom to move through pages. Filter to something with no matches and you get an empty state with a Clear filters button rather than a blank table.

Rebalancing tab

Overnight, vehicles pile up where journeys end — the city centre — and drain away from residential areas. This tab decides which vehicles to move where.

The supply table

ColumnMeaning
ZoneArea of the city
HaveVehicles available there now
TargetHow many it should have, based on forecast demand
GapHave minus Target. Green means spare, red means short.
Short ← → SpareThe same gap drawn as a bar, for scanning quickly
Target is each zone's share of the vehicles that actually exist, weighted by predicted demand — not a wish list. Rebalancing cannot create vehicles; it only decides where the ones you have should stand. That is why the gaps always add up to roughly zero.

The controls

ControlWhat it does
VansHow many rebalancing vans are available
Capacity eachHow many vehicles fit in one van
Worth driving N kmHow far a van will drive to place one vehicle
Demand horizonHow far ahead to forecast — 1 to 8 hours

Solving

  1. Adjust the controls if you want.
  2. Press Solve rebalancing.
  3. A plan card appears showing imbalance closed and van kilometres — the benefit and its cost.
  4. Below it, the crew tasks: move N vehicles from one zone to another, longest journey first.
  5. Mark each task Done or Skip as crews work through it. When none are left outstanding, the plan marks itself completed.
Try dragging worth driving N km down to 1 and solving again. The plan empties, and the app explains why: no move is worth making at that value. This is the real operational trade-off — driving a scooter across town for one extra journey is not work worth doing.
The tasks are ordered longest journey first on purpose. If a shift is cut short, the moves left undone are the ones that were hardest to justify anyway.

9 · Data — the prediction model

Data /data View: all · Retrain: admin, analyst

This screen is the machine learning part of the project: a model that predicts how many trips each zone will need, in 15-minute slots.

Headline figures

FigureMeaningCurrent
MAEMean Absolute Error — average size of the model's mistakes. Lower is better.0.242
Baseline MAEError of a simple rule: "same as this time last week"0.610
Skill ratioModel error ÷ baseline error. Below 1 means the model beats the simple rule.0.397
A skill ratio of 0.397 means the model's errors are about 40% the size of the simple rule's. The design document set a target of 0.70 or better, so this comfortably passes. Comparing against a baseline matters: a model with a small error is only impressive if guessing would have done worse.

Forecast — one zone at a time

Predicted trips for the next three hours in 15-minute slots. The shaded band is the 80% interval — the model expects the real value to land inside it 4 times out of 5. Use the zone selector to change zones.

A forecast never appears as a bare number here. A prediction without a range hides how confident the model is, and a planner acting on the middle line alone would be over-trusting it.

One zone at a time is deliberate — eight overlapping lines on one chart would need eight distinguishable colours, and no palette stays readable at that count.

Model registry

Every model version ever trained, with columns Version, Algorithm, Baseline, Skill and State (Active or Inactive).

Only one model is Active. A model that has no recorded evaluation, or misses the target, is stored but left inactive — it is kept for the record, not used for predictions. This is what stops an untested model quietly going live.

Retrain model

There is a Retrain model button. Pressing it queues a training job in the background and the button shows Queuing…. Training takes around 30 seconds; refresh after a moment and the new version appears in the registry.

Two things about this button:
  • It is visible to everyone, but only admins and analysts can use it. Other roles get a permission error. The permission is enforced by the server, not by hiding the button.
  • Retraining is a background job, not an instant action. Nothing appears to happen at first — that is expected. Do not press it repeatedly.

A horizontal bar chart of net flow per zone — journeys that ended there minus journeys that started there.

  • Positive (right) — more journeys end here than start. Vehicles pile up overnight.
  • Negative (left) — more journeys start here than end. The zone is stripped by morning.
This chart and the Rebalancing tab describe the same problem from opposite ends. This one shows vehicles draining out of Shahapur; the rebalancing planner is what moves them back.

Modal split and emission factors

Modal split shows the share of journeys by vehicle type as labelled bars. Below it, the emission factors used in the CO₂ calculation, each with a cited source — hover to read it.

The CO₂ figure rests on an assumption printed right beside it: each trip is assumed to replace a car trip of equal distance. Stating it lets a reader who disagrees see exactly what they are disagreeing with, instead of the assumption hiding in the code.

Per zone table, and export

A table of every zone with journeys started, ended, net flow, distance and CO₂ saved. The Export CSV button downloads the daily figures as a spreadsheet file.

Charging tab

Where charging stations are, and how to add one.

Adding a station

  1. Click anywhere on the map. A blue marker appears where you clicked, labelled New station here.
  2. Type a Name, e.g. "Vadgaon Market".
  3. Set Charge points (how many vehicles can charge at once) and kW each (charging power).
  4. Choose a Status:
    • Active — riders can see it on the Plan screen
    • Planned — recorded but not yet built, hidden from riders
    • Offline — temporarily out of service
  5. Press Add station. It appears in the list and on the map immediately.
You are not asked which zone the station is in. The application works that out from where you clicked — so the two can never disagree.

The list on the right shows every station with its charge points, power, coordinates and status, and a Remove button. Removing hides it from riders but keeps the record, so past journeys that referenced it still make sense.

The best thing to demonstrate here: the Sim screen says unmet demand is caused by flat batteries. Add a station in a zone that is short, and you have responded directly to a finding the simulation produced.

11 · The public data feed

The application publishes its fleet in GBFS — General Bikeshare Feed Specification, the open standard journey planners use. It needs no login. Open it in any browser tab:

http://localhost:4000/gbfs/2.3/gbfs.json               # index of all feeds
http://localhost:4000/gbfs/2.3/system_information.json # about the system
http://localhost:4000/gbfs/2.3/vehicle_types.json      # the four vehicle types
http://localhost:4000/gbfs/2.3/free_bike_status.json   # available vehicles now
Two privacy rules are enforced in the feed, not merely intended:
  • Only available vehicles are published. A vehicle being ridden would reveal a rider's live location, and the feed has no login.
  • Vehicle IDs change every hour. Otherwise anyone polling the feed could follow one vehicle across days and reconstruct its rider's movements.

12 · Common tasks, step by step

Plan a journey and find a scooter

  1. Sign in. Click Plan.
  2. Press Sample trip — or click the map twice.
  3. Read the three route cards; click one to see its four measures.
  4. Scroll to Available near your pickup for vehicles and their batteries.
  5. Scroll to Charging on the way for stations along your chosen route.

Find out whether bike lanes are worth building

  1. Click Sim.
  2. Select Baseline — typical weekday and press Run simulation.
  3. Select Protected bike lanes — city centre and run that too.
  4. With bike lanes still selected, set Compare against to the baseline.
  5. Read the incident rate row: about 31% lower, while trips served slightly increased.

Move vehicles to where they are needed

  1. Click Fleet, then the Rebalancing tab.
  2. Read the supply table — red gaps are short zones, green are oversupplied.
  3. Press Solve rebalancing.
  4. Read the plan: imbalance closed, and the van kilometres it costs.
  5. Mark tasks Done as you go.

Add a charging station where the simulation says one is needed

  1. On Sim, note the unmet-demand reason: no charged vehicle.
  2. Go to Admin → Charging.
  3. Click the map where cover is thin — the residential edges.
  4. Name it, set charge points and power, press Add station.
  5. Go back to Plan, route through that area, and see it appear under Charging on the way.

Export figures for a report

  1. Click Admin, stay on Analytics.
  2. Choose a Range.
  3. Press Export CSV. Open the file in Excel or LibreOffice.

15 · What the application does not do

Knowing the edges is part of knowing the tool. These are deliberate decisions, not unfinished work.

Not availableWhy
Booking or renting a vehicleThis is the planning layer beneath a rental service, not the service itself. You can plan a journey and see which vehicles are available, but not unlock one.
PaymentsNo card data touches this system by design. A half-built payment path would be a liability.
Docking stations and parking rulesNot built. Vehicles are free-floating within zones.
Notifications and messagingNot built, though live updates already reach the screen.
Emergency responseNot built — it depends on incident detection that is only partly built.
Searching by street nameSet points by clicking the map. There is no address search box.
