AI Urban Micro Mobility Simulator

How to set up and run the project

From a fresh Windows computer to the app running in the browser. Linux and macOS differences are marked where they matter.

Written 24 November 2026 for the main branch at commit 363084e · Repository: github.com/stark-03/micromobility_project

1. What you are running

The project is four programs that run together. All four must be running for the app to work fully.

ProgramAddressWhat it does
MySQL 8.4port 3306*The database: users, vehicles, trips, stations, the road network.
API (Node.js)localhost:4000The server the app talks to. Logins, rentals, roles, live updates.
ML service (Python)localhost:8000Route planning, demand forecasts and the city simulation.
Web app (React)localhost:5173What you open in the browser.

* Whatever port you chose when installing MySQL. Section 4 shows how to find it.

2. Install these first

Do not use XAMPP's database. XAMPP ships MariaDB, not MySQL. The project's map data uses MySQL 8 features MariaDB does not have, so migrations fail and micromobility.sql will not import. If XAMPP is installed, either stop its MySQL or give MySQL 8.4 a different port (for example 3307) during installation.

3. Get the code

git clone https://github.com/stark-03/micromobility_project.git
cd micromobility_project
npm install
npm run build -w @mm/shared-types

The last command builds the shared rules package (including who can open which screen). The API will not start without it, so run it again whenever you pull new code.

4. Create the database

Find MySQL's port

In Command Prompt:

netstat -ano | findstr LISTENING | findstr :330

A line like 0.0.0.0:3305 … LISTENING means MySQL is on port 3305. Ignore 33060 (a different MySQL protocol). If nothing appears, open services.msc and start the MySQL84 service.

Create the databases and the app's user

Open MySQL Workbench. On its home screen click + next to MySQL Connections; set Hostname 127.0.0.1, the Port you just found, Username root; click Test Connection and enter the root password you chose while installing. Open the connection and run:

CREATE DATABASE micromobility      CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE DATABASE micromobility_test CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

CREATE USER 'mm_app'@'localhost' IDENTIFIED BY 'change_me';
GRANT ALL PRIVILEGES ON micromobility.*      TO 'mm_app'@'localhost';
GRANT ALL PRIVILEGES ON micromobility_test.* TO 'mm_app'@'localhost';
FLUSH PRIVILEGES;
Workbench says offline? It is only a viewer; the database is the MySQL84 service. "Offline" almost always means the connection's port is wrong. Edit the connection and use the port from netstat.

5. Create the settings file (.env)

In the project folder, copy the template:

Windows:      copy .env.example .env
Linux/macOS:  cp .env.example .env

Open .env in a text editor and change these lines:

DB_HOST=127.0.0.1
DB_PORT=3306                 # the port from section 4
DB_USER=mm_app
DB_PASSWORD=change_me        # what you set in CREATE USER
DB_NAME=micromobility
DB_NAME_TEST=micromobility_test

JWT_ACCESS_SECRET=           # paste a generated secret
JWT_REFRESH_SECRET=          # paste a DIFFERENT generated secret

Generate each secret with this command (run it twice, one value per line):

node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
.env holds passwords and secrets. It is ignored by git: never commit it, never paste it into chat or screenshots.

6. Load the data

Choose one option. Run all commands from the project's root folder.

Option A — import the shared database dump (recommended for a demo)

micromobility.sql is not in the repository (it contains user accounts and password hashes). Get it from a teammate by USB or Drive. Then, in Command Prompt (not PowerShell):

"C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe" -h 127.0.0.1 -P 3306 -u root -p micromobility < micromobility.sql

Use your port after -P. It prints nothing for a minute while it works. Then bring the imported data up to date:

npm run db:migrate
npm run db:seed
npm run demand:backfill
npm run rollup

The demo accounts in Section 9 work with this option.

Option B — start from an empty database

npm run db:migrate
npm run db:seed              # prints the demo passwords ONCE: copy them now
npm run demand:backfill
npm run rollup
CommandWhat it does
db:migrateCreates and updates all tables. Safe to run any time.
db:seedLoads the Belagavi city: roads, zones, stations, vehicles, demo accounts. Safe to re-run; it never changes existing passwords.
demand:backfillGenerates six weeks of trip history up to today, which the demand model trains on.
rollupBuilds the daily summaries the Admin analytics dashboard reads.

7. Set up the Python ML service (once)

Open Anaconda Prompt (Windows) or a terminal (Linux/macOS):

cd micromobility_project\apps\ml
conda create -n micromobility python=3.12 -y
conda activate micromobility
python --version             # must say 3.12.x before you continue
pip install -r requirements.txt
Python 3.12 exactly. With a newer Python, pip tries to compile LightGBM and NumPy from source, which fails on Windows. If pip install fails anyway, install the heavy packages from conda-forge first, then repeat the pip line:
conda install -c conda-forge numpy=2.1.3 pandas=2.2.3 scikit-learn=1.6.0 lightgbm=4.5.0 scipy -y

8. Start the project (every time)

MySQL starts with Windows by itself. Open three terminals and leave each one running.

Terminal 1 — ML service Anaconda Prompt

cd micromobility_project\apps\ml
conda activate micromobility
uvicorn app.main:app --reload --port 8000

Run it from inside apps\ml, or you get No module named 'app'. On Linux/macOS npm run dev:ml from the root does all three lines.

Terminal 2 — API

cd micromobility_project
npm run dev:api

Ready when it prints "API listening","port":4000.

Terminal 3 — web app

cd micromobility_project
npm run dev:web

Then open http://localhost:5173.

CheckExpected
http://localhost:4000/healthzAPI: a response containing "status":"ok"
http://localhost:4000/readyzAPI plus its database and ML service: each listed as up or down
http://localhost:8000/healthzML service: a response containing "status":"ok"
http://localhost:8000/404 Not Found: normal, the ML service has no home page

Once, after setup

  1. Admin analytics empty ("No rollups yet")? Sign in as admin and press Build now.
  2. Data → forecast empty? Sign in as admin or analyst, open Data, press Retrain model. The model is kept in the ML service's memory, so retrain after every ML restart.

Showing live updates

Sign in as admin in a normal window and as commuter in an Incognito/InPrivate window (two tabs of one window share one login). Open Fleet as admin; rent a vehicle on Ride as commuter; the Fleet counts and rider column change within a second.

Free map or Google

Every map has a Free map | Google switch at the top right. Google shows Google's own map of the same spot for checking positions; routes and stations are drawn only on the free map. No Google key or card is needed.

11. When something goes wrong

You seeCause and fix
Table 'micromobility.roles' doesn't exist when seedingTables were never created. Run npm run db:migrate, then seed.
Migration fails on SRID, or the dump will not importYou are connected to XAMPP's MariaDB. Use MySQL 8.4 and its port (sections 2 and 4).
ECONNREFUSED … :3306 in the API terminalDB_PORT in .env is not MySQL's port. Check with netstat.
Access denied for user 'mm_app'DB_USER/DB_PASSWORD do not match the CREATE USER you ran.
Missing required env var: JWT_ACCESS_SECRETFill in both JWT secrets in .env (section 5).
Sign-in says "Something went wrong"; web terminal shows http proxy error … ECONNRESETThe API is not running or is restarting. Look at the API terminal; fix its error and press Sign in again.
API will not start: cannot find @mm/shared-types or ACCESSRun npm run build -w @mm/shared-types.
Place search returns 500; log says Illegal mix of collationsOld code. Pull the latest main (fixed there).
Data screen: No demand model has been trained yetPress Retrain model. If training never starts, run npm run demand:backfill first: training needs trips from the last six weeks.
Plan screen: NO_ROUTE_FOUND / SERVICE_UNAVAILABLEThe ML service is not running (Terminal 1), or the point is more than 750 m from any road.
No module named 'app' starting the ML serviceStart uvicorn from inside apps\ml.
pip fails compiling LightGBM / NumPyThe conda environment is not Python 3.12. Recreate it (section 7).
Port 5173 is in useAnother project is running there. Stop it, or run npx vite --port 5174 in apps\web.
Admin: "No rollups yet"Press Build now, or run npm run rollup.
Pins in the wrong place on the mapOld seed data. Pull main and run npm run db:seed; it moves every station to its real position.
Too many requests (429)The API allows 100 requests a minute per user. Wait a minute.
